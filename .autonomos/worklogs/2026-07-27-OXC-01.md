# OXC-01 — Native Oxc tooling evaluation

## What was done

- Loaded the official Oxc migration skills and reviewed current TypeScript 7, Oxlint, and Oxfmt documentation.
- Audited the Tala ESLint/Prettier packages and representative Node, Next/Tailwind, and Storybook consumers in `commerce`, `agency`, and `selto`.
- Ran Oxc migrations and read-only comparisons against `agency/apps/portfolio`; all generated configuration and formatted copies were kept in `/tmp`.

## Key decisions

- The Oxfmt package decision remains open: its native import sorting produced 405 file differences versus the current Prettier + organize-imports output (180 differences without sorting), but the user accepts this one-time migration diff when Oxfmt maintains a stable order afterward.
- A native-only `@tala-tools/oxlint` remains viable: the representative Next configuration migrated 103 rules without JS plugins, including TypeScript, React, and Next.js rules.
- Do not carry `eslint-plugin-regexp` or `eslint-plugin-better-tailwindcss` through Oxlint JS plugins. They account for 68 skipped rules, require direct consumer dependencies under pnpm, and conflict with the native-first performance goal.
- Keep type-aware linting as a separately evaluated opt-in: the migration skipped `@typescript-eslint/no-misused-promises`; Oxlint's `oxlint-tsgolint` integration uses TypeScript 7 but adds setup and monorepo constraints.

## Evidence

- TypeScript 7 is stable and its official announcement reports an approximately 10x speed-up; its programmatic API is not yet stable.
- Oxfmt checked 607 TypeScript/TSX files in 62–65 ms using 16 threads; the current Prettier check took about 5.7 s in the same warm environment.
- Native Oxlint completed a clean traversal of the same `src` tree in about 270 ms. The current ESLint configuration still produced diagnostics through its type-aware and plugin-backed rules.
