# OXC-05 — Prepare Oxc packages for publication readiness

## What was done

- Added the repository Node.js support floor (`>=20.19.0`) to both new packages.
- Added and validated the optional TypeScript 7 type-aware Oxlint preset through
  `oxlint-tsgolint`.
- Checked formatting, Oxlint, JavaScript declaration compatibility, and publint
  for `@tala-tools/oxfmt` and `@tala-tools/oxlint`.
- Inspected the generated package archives and verified that each contains only
  `README.md`, `package.json`, `index.js`, and `index.d.ts`.
- Confirmed that both scoped package names are not yet registered on npm.
- Scoped the root Oxc verification commands to the new packages and their
  configs, preserving the existing repository files until their deliberate
  one-time Oxfmt migration.

## Key decisions

- Keep the initial release version at `0.0.1`; no changeset is needed for an
  unpublished initial package release.
- Do not publish yet. The commerce consumer continues to use local `link:`
  dependencies until the release commit is reviewed and accepted.
- Keep Oxfmt and Oxlint package peers explicit and optional where the preset is
  optional, so non-Tailwind and non-type-aware consumers have no forced plugin
  dependency.
