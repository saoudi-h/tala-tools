# OXC-06 — Queue initial Oxc package release through Changesets

## What was done

- Added a patch changeset for `@tala-tools/oxfmt` and `@tala-tools/oxlint`.
- Set both unpublished package manifests to `0.0.0`, allowing Changesets to
  calculate their intended initial public release as `0.0.1`.
- Rebased the Oxc commits onto the release commit that landed on `main` while
  this work was in progress.
- Revalidated the Changesets result, Oxlint, and Oxfmt after the rebase.
- Pushed the release queue to `origin/main` at `2b26975`.

## Key decisions

- Use the repository's Changesets workflow instead of invoking npm publish
  directly.
- Keep only the two new Oxc packages in the release queue; the previously
  pending package releases were already consumed by the upstream release
  commit.

## Next steps

- The GitHub Changesets workflow will create its versioning release pull
  request. Merge that pull request to publish the two `0.0.1` packages.
- After publication, replace the commerce pilot's local `link:` dependencies
  with the released package versions before adopting the tooling in more
  projects.
