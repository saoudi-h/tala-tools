# TSC-01 — Replace bun.json with bun-*.json suite

## Context
ISSUE-001: `packages/tsconfig/bun.json:5` used `types: ["bun-types"]` which fails `TS2688` on clean install with `@types/bun@1.4.0` (Herald). Stale local symlink masked failure. Needed isolated Bun suite, not mixing DOM/Node libs.

## Decisions
- Do not mutate `base.json:1-25`, `nextjs.json`, `react-library.json` (keep Node/Browser family).
- Replace `bun.json` with 3 files: `bun-base.json` (equiv base for Bun, `lib:["ESNext"]`, `types:["bun"]`, `module:Preserve`, `verbatimModuleSyntax:true`), `bun-next.json` (extends bun-base + DOM + next plugin), `bun-react-library.json` (extends bun-base + DOM).
- No `bun-remotion.json` / niche presets without consumer.
- Remove `bun.json`, update `package.json:12-18` exports and `README.md:24-30`, `AGENT.md:1-5`.

## Validation
- `tsc --showConfig` for `bun-base.json` shows `types:["bun"]`, `lib:["esnext"]`, `module:preserve` correctly.
- Clean consumers `/tmp/opencode/bun-consumer`, `bun-next-consumer`, `bun-react-consumer` with `pnpm add @types/bun@1.4.0` + `extends @tala-tools/tsconfig/bun-*.json` → `tsc --noEmit` passes (exit 0).
- Old `types:["bun-types"]` consumer with only `@types/bun` fails `TS2688` as expected (reproduced).
- `pnpm --filter @tala-tools/wt typecheck` and `pnpm typecheck` (turbo) pass — Node consumers unaffected.
- `pnpm changeset status` shows `minor` bump for `@tala-tools/tsconfig`.

## Outcome
Fixes ISSUE-001 reproducible clean install, documents Node vs Bun runtime assumptions, prevents drift via clean consumer pattern.
