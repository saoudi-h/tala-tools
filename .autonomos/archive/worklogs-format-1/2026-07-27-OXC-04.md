# OXC-04 — Stabilize Oxc presets and commerce pilot

## What was done

- Made `better-tailwindcss` the Tailwind style authority in `@tala-tools/oxlint`.
- Disabled Oxfmt Tailwind sorting in `@tala-tools/oxfmt` to prevent conflicting class ordering and wrapping fixes.
- Downgraded the native Oxlint correctness category and unused-variable findings to warnings during migration.
- Revalidated both packages and reran the local `commerce` pilot without modifying storefront source files.

## Results

- `publint`, Oxfmt, and Oxlint validation pass for both new Tala packages.
- Commerce Oxfmt now reports 383 initial formatting changes, down from 436, and checks 814 files in about 325 ms.
- Commerce Oxlint now reports 816 warnings and zero errors. The pilot is informative without blocking the existing build or lint workflow.

## Key decisions

- Oxfmt owns general formatting and import sorting.
- `better-tailwindcss` owns Tailwind class ordering, line wrapping, and correctness validation through Oxlint.
- New native Oxlint rules start as warnings; promote them selectively only after reviewing the existing ESLint baseline.

## Next steps

- Review the Oxlint warning set by rule family and select the rules to enforce as errors.
- Run a dedicated formatting branch for the 383 Oxfmt changes once the output is accepted.
- Keep ESLint and Prettier in parallel until the first consumer migration is accepted.
