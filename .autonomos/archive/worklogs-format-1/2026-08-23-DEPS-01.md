# DEPS-01 — Refresh dependencies and formalize dual TypeScript coexistence

## What was done

- Updated available stable dependency releases across the root, ESLint, tsdown,
  and wt manifests, including Oxlint/Oxfmt, Turbo, commitlint, ESLint plugins,
  Vitest, Node types, and publint.
- Kept the root toolchain on exact TypeScript `7.0.2`.
- Added exact TypeScript `6.0.3` to `@tala-tools/eslint` so its legacy
  `typescript-eslint` toolchain resolves a supported compiler locally.
- Retained exact TypeScript `6.0.3` and tsdown `0.21.7` in `@tala-tools/tsdown`.
  tsdown `0.22.x` remains unsuitable for the package's Node `>=20.19.0`
  compatibility promise because its dts plugin requires Node `>=22.18.0`.
- Migrated `@tala-tools/wt`'s Zod function schemas to the Zod 4 API exposed by
  the resolved dependency, preserving the existing hook signatures.
- Extended the existing Changeset to publish patch versions of `@tala-tools/eslint`,
  `@tala-tools/tsdown`, and `@tala-tools/wt`.
- Documented the intentional dual-TypeScript setup in the root agent guidance.

## Validation

- `pnpm install`
- `pnpm build`
- `pnpm typecheck`
- `pnpm lint`
- `pnpm --filter @tala-tools/wt test` — 48 tests passed
- `pnpm oxfmt`
- `pnpm oxlint`
- `pnpm changeset status` — three patch releases queued

## Deferred

- `@changesets/cli` 3.0.1 remains deferred because it is a release-CI major
  upgrade unrelated to TypeScript 7.
- TypeScript 7 remains intentionally unavailable to the `@tala-tools/tsdown`
  package's own dts toolchain until the Node engine constraint is relaxed or a
  compatible tsdown/dts stack is released.
